# C for C++ 程序员 · 速查

## 1. 语言层面：C 里没有的东西

| C++ | C 的替代做法 | 备注 |
|---|---|---|
| `class` / 成员函数 / 继承 / 虚函数 | `struct` + 独立函数，函数名带前缀 | 多态靠**函数指针表**手工实现（见 `ex09`） |
| `T&` 引用 | `T*` 指针 | 传"输出参数"要用 `T*`，调用时写 `&x` |
| 函数重载 / 默认参数 | 一个函数一个名字 | 靠命名区分：`print_i` / `print_f` |
| `template` | `void*` + 强转，或宏 | 泛型容器基本靠宏写 |
| `namespace` | 名字前缀 `mylib_xxx` | |
| `new` / `delete` | `malloc` / `free` | malloc 只给裸内存，**不调用构造** |
| `std::string` | `char buf[N]` + `'\0'` | |
| `std::vector` | `malloc` + 手写扩容 | 嵌入式里通常干脆用定长数组 |
| `try/catch` / 异常 | 返回错误码 + `errno` | C 没有栈展开 |
| `bool/true/false` | `#include <stdbool.h>` | C99 起 |
| `nullptr` | `NULL`（来自 `stddef.h`） | 本质是 `((void*)0)` 或 `0` |
| 变量随用随定义 | C99 起可以，C89 不行 | 工程上仍习惯集中在函数头 |
| RAII 自动释放 | 手动配对，`goto cleanup` 是常见惯用法 | 没有析构函数 |
| `std::cout` | `printf` | 格式符要手写，写错就是 UB |

## 2. 类型宽度（嵌入式的命根子）

`int` 的宽度**不保证**是 4 字节。要精确控制就得用 `<stdint.h>`：

| 类型 | 含义 | 嵌入式用途 |
|---|---|---|
| `uint8_t` / `int8_t` | 恰好 8 位 | 寄存器、字节缓冲 |
| `uint16_t` / `int16_t` | 恰好 16 位 | ADC 采样值 |
| `uint32_t` | 恰好 32 位 | 外设寄存器（STM32 基本都是这个） |
| `size_t` | 无符号，能装下任何对象大小 | `sizeof` 的返回类型，`malloc` 的参数 |
| `intptr_t` / `uintptr_t` | 能装下指针的整数 | 指针和整数互转时用 |

**陷阱**：`sizeof` 返回 `size_t`（无符号）。`for (int i = n; i >= 0; i--)` 里如果 `n` 是 `size_t`，比较会隐式转无符号。以及 `if (strlen(s) - 1 >= 0)` 永远为真。

## 3. 内存布局（必须背下来）

```
高地址
┌─────────────────────┐
│  命令行参数 / 环境变量  │
├─────────────────────┤
│  栈 stack            │  局部变量、函数参数、返回地址
│  ↓ 向低地址增长        │  自动回收，容量有限（默认 1–8 MB）
├─────────────────────┤
│  ...空闲区...         │
├─────────────────────┤
│  堆 heap             │  malloc/calloc/realloc 在这里
│  ↑ 向高地址增长        │  必须手动 free，不会自己回收
├─────────────────────┤
│  BSS                 │  未初始化的全局 / static（启动时清零）
├─────────────────────┤
│  数据段 .data         │  已初始化的全局 / static
├─────────────────────┤
│  代码段 .text         │  机器指令，只读；字符串字面量常在这里
└─────────────────────┘
低地址
```

在 STM32 上这张图**不是理论**，而是真实的地址区间（Flash 从 `0x08000000` 起，SRAM 从 `0x20000000` 起），链接脚本决定的。启动文件里会把 `.data` 从 Flash 拷到 SRAM、把 `.bss` 清零——这两件事你在 PC 上从没关心过，在单片机上必须自己保证。

## 4. 指针 · 反直觉五连

```c
int a[5];
int *p = a;          // 数组名退化为 &a[0]
p + 1;               // 不是 +1 字节，是 +sizeof(int) 字节
*(p + 2) == p[2];    // 完全等价，下标就是指针算术的语法糖
sizeof(a) == 20;     // 只有这里 a 不退化
&a + 1;              // 跳 20 字节（整个数组），类型是 int(*)[5]
```

`const` 的位置——**从右往左读**：

```c
const char *p;        // p 可以改，指向的字符不能改（最常用）
char * const p = b;   // p 不能改，指向的内容可以改
const char * const p; // 都不可改
char * const * p;     // 指针的指针，内层指针不可改
```

指针数组 vs 数组指针：

```c
int *arr[10];    // 指针数组：10 个 int*
int (*arr)[10];  // 数组指针：1 个指针，指向「10 个 int 的数组」，+1 跳 40 字节
```

## 5. 字符串

```c
char s1[] = "hello";   // 可改，6 字节（含 '\0'）
char *s2 = "hello";    // 指向只读区，s2[0]='H' 是 UB（可能段错误）
```

`<string.h>` 必背：

| 函数 | 作用 | 危险点 |
|---|---|---|
| `strlen(s)` | 到 `'\0'` 的长度 | O(n)，别放循环条件里 |
| `strcpy(d, s)` | 复制 | **不检查 d 的大小**，溢出 |
| `strncpy(d, s, n)` | 限长复制 | `s` 比 `n` 短时**不补 `'\0'`** |
| `strcat(d, s)` | 追加 | 同样不检查大小 |
| `strcmp(a, b)` | 比较 | 返回 0 才相等，别写 `if (strcmp())` |
| `memcpy/memset` | 内存块操作 | `memcpy` 重叠区域是 UB，要 `memmove` |
| `snprintf(buf, n, ...)` | **最安全的格式化** | 优先用它，别用 `sprintf` |

## 6. printf 格式符速查

| 符 | 类型 | 例 |
|---|---|---|
| `%d` `%i` | `int` | |
| `%u` | `unsigned` | |
| `%ld` `%lld` | `long` / `long long` | |
| `%zu` | `size_t` | `printf("%zu", sizeof(int))` ← **正解** |
| `%x` `%X` | 十六进制 | 看寄存器必备 |
| `%08X` | 8 位、补前导零的十六进制 | `0x0000A5C3` |
| `%f` | `double` | `%f` 默认 6 位小数，`%.2f` 两位 |
| `%c` | `char` | |
| `%s` | 字符串 | |
| `%p` | 指针 | 打印地址 |

对齐 `int` 和 `long` 搞错的后果：C 是可变参数，**类型不匹配就是 UB**，64 位 Windows 上 `%d` 打 `long long` 会打出垃圾。

## 7. 未定义行为（UB）黑名单

这些在 PC 上"有时能跑"，在单片机上直接 HardFault：

1. 越界读写数组 / 字符串（包括少写一个 `'\0'`）
2. 解引用野指针、已 `free` 的指针（use-after-free）
3. 同一块内存 `free` 两次
4. 有符号整数溢出（`INT_MAX + 1`）
5. 左移位数 ≥ 类型宽度，或对负数左移
6. 修改字符串字面量
7. 未初始化变量就读（值不确定）
8. 空指针解引用
9. 类型双关用错（`float*` 强转 `int*` 再解引用）
10. `memcpy` 源与目标重叠

编译时开 `-Wall -Wextra -Wpedantic`，运行时用 `-fsanitize=undefined` 抓一半以上。

## 8. 头文件与分离编译

```c
/* gpio.h —— 只放声明 */
#ifndef GPIO_H          /* 头文件守卫，防止重复包含 */
#define GPIO_H

#include <stdint.h>

typedef struct {
    volatile uint32_t MODER;
    volatile uint32_t ODR;
} GPIO_TypeDef;

void gpio_init(GPIO_TypeDef *port, uint32_t pin);
void gpio_toggle(GPIO_TypeDef *port, uint32_t pin);

#endif /* GPIO_H */
```

规则：

- **声明放 `.h`，定义放 `.c`**。头文件里绝不能有函数定义（否则多文件链接时重复定义）。
- `static` 修饰函数/全局变量 = 只在本文件可见（嵌入式里用来做"私有"）。
- `extern` = 声明"这个变量在别处定义了"。
- 编译分两步：`gcc -c` 生成 `.o`，再 `gcc *.o -o app.exe` 链接。链接器负责把跨文件的符号对上。

---

**一句话总结**：C++ 教你"不要碰内存"，C 逼你"亲手管内存"。前 6 小时你会觉得处处别扭，第 10 小时开始你会开始享受这种"每一字节都在我掌握中"的感觉——而这正是写单片机的前提。
