# 从 PC 上的 C 到 STM32 上的 C

这份笔记的作用：让你在 PC 上写完这 12 个练习后，**知道哪些习惯要保留、哪些要改**。

---

## 1. 变化最大的一件事：没有操作系统兜底

PC 上你写 `int *p = NULL; *p = 1;`，操作系统会给你一个"段错误"，程序死掉但系统没事。

STM32 上没有 MMU、没有操作系统（裸机时），你写 `*(uint32_t*)0x20000001 = 1;`：

- 有可能**什么都不发生**（写进了不存在的内存，被总线忽略）
- 有可能**静默改掉了别的变量**
- 有可能触发 **HardFault**，程序停在一个死循环里，没有任何提示

**结论：PC 上"能跑"不等于"对"。这就是为什么练习里我要求你 `-Wall -Wextra -Wpedantic` 一个警告都不能有，还要主动找 UB。**

---

## 2. 从"调库"变成"读手册 + 写地址"

PC 上操作硬件，你调的是系统 API。STM32 上，硬件就是**一片固定地址的内存**：

```c
/* PC：malloc 出来的内存是"无意义"的，随便写 */
uint32_t *buf = malloc(4);
*buf = 0x1;

/* STM32：地址是"有意义"的，写了就会改变物理引脚 */
#define GPIOA_BASE  0x40020000UL
#define GPIOA_ODR   (*(volatile uint32_t *)(GPIOA_BASE + 0x14))
GPIOA_ODR |= (1U << 5);   /* PA5 输出高电平 */
```

`ex10_mmio_volatile.c` 就是用普通内存模拟这套机制，让你先在 PC 上把这个模式练熟。

厂商头文件（`stm32f103xb.h`）干的就是这件事——把上千个地址包装成 `GPIOA->ODR` 这样的结构体成员。你学完 `struct` 和 `volatile` 之后再看它，会发现完全能读懂。

---

## 3. `volatile` —— 单核 PC 上几乎用不到，单片机上天天用

```c
volatile uint32_t *reg = (volatile uint32_t *)0x40020014;
```

告诉编译器：**这个变量可能被"你不知道的力量"改变，每次用都要重新从内存读，不许缓存到寄存器、不许优化掉。**

什么时候必须加：

| 场景 | 为什么 |
|---|---|
| 外设寄存器 | 硬件会改它的值（如状态位），编译器不知道 |
| 中断里会改的全局变量 | 主循环读它，中断改它 |
| 多线程共享变量 | 同理 |
| 空的延时循环 `for(i=0;i<1000;i++);` | 不加 `volatile`，`-O2` 会把整个循环删掉 |

**`volatile` 不保证原子性**。`reg |= (1U<<5)` 是"读-改-写"三步，中断里同时改同一个寄存器会丢更新。这是嵌入式的经典坑。

---

## 4. 尽量不用 `malloc`

嵌入式里 `malloc` 有这些问题：

- 堆很小（STM32F103 一共 20 KB SRAM，堆能分到的可能只有几 KB）
- 分配/释放会产生**碎片**，跑几天后分配失败
- 大部分嵌入式规范（MISRA、DO-178C）**禁止动态内存**
- 无法保证 malloc 返回非 NULL 之后就一直可用

**替代方案**：

```c
/* 用静态数组 + 记录长度 */
#define MAX_ITEMS 64
static Item pool[MAX_ITEMS];
static size_t pool_count = 0;

/* 或者静态分配一大块，自己写内存池 */
static uint8_t heap_pool[4096] __attribute__((aligned(8)));
```

所以：`ex06` 的动态数组练习，**目的是让你理解内存管理，不是让你在 STM32 上这么写。**

## 5. 位运算 = 嵌入式的日常语言

PC 上你很少写位运算，STM32 上你 80% 的时间在写它：

```c
reg |=  (1U << 5);        /* 把第 5 位置 1 —— 打开某个功能 */
reg &= ~(1U << 5);        /* 把第 5 位清 0 —— 关闭 */
reg ^=  (1U << 5);        /* 翻转第 5 位 —— 切换 */
if (reg & (1U << 5)) {}   /* 检查第 5 位 —— 查状态 */

/* 改一个多位字段（比如把 4~6 位设成 0b101）*/
reg &= ~(0x7U << 4);      /* 先清干净 */
reg |=  (0x5U << 4);      /* 再写入 */
```

**为什么到处是 `1U << n` 而不是 `1 << n`**：`1` 是有符号 `int`，左移 31 位是 UB。加 `U` 变成无符号，行为确定。这是嵌入式代码风格里最容易被忽略的细节。

`ex08_bitops.c` 会把这一整套练成肌肉记忆。

## 6. 从 `main` 到真正跑起来

PC 上：双击 exe → 操作系统调 `main`。

STM32 上（复位后）的顺序是：

```
上电 / 复位
  → 从 Flash 起始地址取「栈顶地址」，初始化 SP
  → 取「复位向量」，跳进 Reset_Handler（启动文件 startup_stm32f103xb.s）
  → 把 .data 段从 Flash 复制到 SRAM
  → 把 .bss 段清零
  → 调用 SystemInit()（配时钟）
  → 调用 __libc_init_array()（C++ 全局构造；纯 C 也有）
  → 调用 main()
  → main() 永远不返回（真的返回了就跳进死循环）
```

这就是为什么**嵌入式里的 `main` 是一个 `while(1)` 超循环**：

```c
int main(void) {
    gpio_init();
    while (1) {          /* 永远不退出 */
        gpio_toggle(LED);
        delay_ms(500);
    }
}
```

`projects/gpio_sim` 里我让你按这个结构写，就是为了提前适应。

## 7. 中断 = 函数指针的终极应用

PC 上的事件循环是 `while(1) { poll(); }`。STM32 上很多事件由**中断**处理：硬件触发，CPU 打断主循环，跳进一个固定地址的函数。

中断向量表本质是**函数指针数组**：

```c
typedef void (*isr_t)(void);

extern void EXTI0_IRQHandler(void);   /* 按键中断 */
extern void TIM2_IRQHandler(void);    /* 定时器中断 */

isr_t vector_table[] = {
    /* 0 */ 0,
    /* 1 */ 0,
    ...
    /* 6 */ EXTI0_IRQHandler,
    /* 7 */ 0,
    ...
    /* 28 */ TIM2_IRQHandler,
};
```

`ex09_function_pointer.c` 就是让你手写这种"回调表 + 分发器"，理解它之后，中断就一点都不神秘了。

## 8. 学习路径（你选的这条路）

```
现在 ─── C 语言（PC + gcc）                    ← 这个练习包，2 天
   │
   ├─ 阶段 1：C 基础 + 内存 + 位运算 + 工程化
   │
   ▼
阶段 2：STM32 裸机                             ← 需要买板子 + 装工具链（先报体积）
   ├─ 点亮一盏 LED（GPIO 输出）
   ├─ 按键控制（GPIO 输入 + 消抖）
   ├─ 串口打印（UART，你的 printf 从这里走）
   ├─ 定时器（TIM，精确延时 / PWM）
   ├─ 中断（NVIC + EXTI）
   └─ 模拟外设（ADC 采集）
   │
   ▼
阶段 3：常用外设（I2C / SPI / 传感器 / 电机驱动）
   ├─ I2C：MPU6050（陀螺仪加速度计，做机器人必备）
   ├─ SPI：OLED 屏 / 无线模块
   └─ PWM：舵机 / 直流电机驱动（TB6612、L298N）
   │
   ▼
阶段 4：RTOS（FreeRTOS）
   ├─ 任务与调度、优先级
   ├─ 队列 / 信号量 / 互斥量
   ├─ 任务间通信（这里你会第一次真正需要 volatile 和临界区）
   └─ 把机器人的"传感器任务 / 控制任务 / 通信任务"拆开跑
   │
   ▼
阶段 5：机器人整机
```

**要不要现在就看 STM32 的东西？** 建议不要。你现在的 C 还没到"看到 `GPIOA->ODR |= (1U<<5)` 能秒懂"的程度，去看 HAL 库只会被一堆看不懂的宏劝退。先把这 12 个练习写完。

## 9. 到 STM32 阶段时要额外装什么（现在别装）

| 方案 | 体积 | 说明 |
|---|---|---|
| STM32CubeIDE | 约 3–5 GB | 官方一体化 IDE，含编译器 + 图形化配置，新手友好但重 |
| `arm-none-eabi-gcc` + VS Code 插件 | 约 1–2 GB | 轻量，但配置步骤多，适合想搞懂原理的人 |
| Keil MDK | 约 1–2 GB | 老牌商业软件，社区版有 32 KB 代码限制 |
| PlatformIO（VS Code 插件） | 约 1 GB | 跨平台统一体验，自动下载工具链，最省事 |

**我推荐 `arm-none-eabi-gcc` + VS Code**，理由是：你已经会用 VS Code + gcc 了，换到交叉编译只是把 `gcc` 换成 `arm-none-eabi-gcc`，心理负担最小，而且你能真正看懂编译过程。

板子推荐：**STM32F103C8T6 最小系统板**（俗称"蓝板"），约 15–25 元，资料最多，够你把 GPIO / UART / TIM / 中断 / ADC / I2C / SPI 全部练一遍。加一个 **ST-Link V2 下载器**（约 10–15 元）就能烧录调试。
